# ImfHeaderWriter Class

## Definition

Namespace: `DataStandardizer.File.InternetMessage`

Represents a writer that provides fast, non-cached, forward-only output of the fields of one header section of an Internet message (RFC 5322 §2.2).

**.NET Standard 1.1:**

```csharp
public sealed class ImfHeaderWriter : IDisposable
```

**.NET and .NET Standard 2.0 and later:**

```csharp
public sealed class ImfHeaderWriter : IDisposable, IAsyncDisposable
```

## Remarks

**Line breaks.** Every line ends in CRLF, whatever the platform.

**Folding.** A field given by name and body is folded at spaces and tabs already in the body, aiming for lines of 78 characters and never passing 998 octets (RFC 5322 §2.1.1 and §2.2.3, RFC 6532 §3.4). No white space is added or removed, except that one space is written after the colon if the body has none, so unfolding gives the same body back. A [`ImfHeaderFieldKind.Structured`](ImfHeaderFieldKind.md) field is not folded inside a quoted string or domain literal. A field that can't be folded within 998 octets is refused, and a line may pass 78 characters when it has nowhere to fold.

**Encoded words.** `WriteTextField` writes text as an unstructured field, with what has to be encoded as RFC 2047 encoded words unless [`ImfOptions.HeaderEncoding`](ImfOptions.md) is [`ImfHeaderEncoding.Utf8`](ImfHeaderEncoding.md). Each word is folded whole, so a line holds at most 76 characters of encoded words. `WriteField(string, string, ImfHeaderFieldKind)` writes a field body as it is given: get a body with encoded words from [`ImfAddress.ToString`](ImfAddress.md), [`ImfAddressList.ToString(ImfHeaderEncoding)`](ImfAddressList.md), [`ImfPhraseList.ToString(ImfHeaderEncoding)`](ImfPhraseList.md) or [`ImfHeaderText.FormatComment`](ImfHeaderText.md).

**Refusals.** A field name must be printable US-ASCII with no colon (RFC 5322 §3.6.8). A body must be given unfolded, with no control characters. It must be US-ASCII, unless [`ImfOptions.HeaderEncoding`](ImfOptions.md) is [`ImfHeaderEncoding.Utf8`](ImfHeaderEncoding.md) and it is valid UTF-8 (RFC 6532). A field that is refused throws [`ImfFileException`](ImfFileException.md) before any of it is written, so writing can continue with the next field.

**Raw passthrough.** A field written from an [`ImfHeaderFieldView`](ImfHeaderFieldView.md) is copied byte for byte, including its folding and line breaks, whichever options it was read under, so that signatures over it stay valid. So are bytes given to `WriteRawField`, once they have been checked to be one whole field.

Nothing is held back from the stream, so a body can be written straight to it after `WriteEndOfHeader`.

Only one operation may be in progress at a time. Synchronous and asynchronous calls may follow one another, but a call made while another is in progress throws `InvalidOperationException`. After a write to the stream fails or is canceled, the writer cannot continue. A write is canceled only when the token passed to it is canceled, whatever token the `OperationCanceledException` carries, or if it carries none. An `OperationCanceledException` while that token isn't canceled, such as one from the stream or the progress callback, is handled as any other exception is.

A file-path constructor opens the file with `FileOptions.Asynchronous`, so the asynchronous methods do no synchronous I/O. To write a file only synchronously, without the small cost that option adds on Windows, pass a `FileStream` opened without it to a `Stream` constructor.

## Applies to

Targets `netstandard1.1`, `netstandard2.0`, `netstandard2.1`, and `net10.0`.
The `string` file-path constructors, the asynchronous methods, and `IAsyncDisposable` are available on `netstandard2.0`, `netstandard2.1`, and `net10.0` only; on `netstandard1.1`, construct it from a `Stream` and work synchronously.
The nullable reference annotations apply to the `netstandard2.1` and `net10.0` builds.
